## 1. 启动方法

### 1.1 依赖

| 组件 | 版本/地址 | 说明 |
| --- | --- | --- |
| Node.js | 18+ | 前端构建 |
| Python | 3.10+（项目内 `.venv`） | 后端运行 |
| Redis / Memurai | `localhost:6379` | 后端强依赖，未启动则后端启动失败 |
| 后端 FastAPI | `http://127.0.0.1:8000` | 接口与 WebSocket |
| 前端 Vite | `http://localhost:5173` | 开发服务器 |

### 1.2 启动命令

```powershell
# 1) 确认 Redis 已监听 6379
netstat -ano | findstr :6379

# 2) 启动后端（在项目根目录）
.\.venv\Scripts\python.exe -m uvicorn main:app --port 8000

# 3) 启动前端
cd frontend
npm install        # 首次运行
npm run dev -- --host
```

- 健康检查：`GET http://127.0.0.1:8000/health`
- 接口文档：`http://127.0.0.1:8000/docs`
- `start.bat` **默认只启动前端**，后端启动行是注释状态，需手动执行上面的 uvicorn 命令。

- Vite 开发服务器所有关键模块（`main.ts`、`App.vue`、`router/index.ts`、各 View）均返回 200。

已对照运行中的 `GET /openapi.json` 及各接口真实响应逐项核对：

| 接口 | 前端发送/期望 | 后端实际 | 结论 |
| --- | --- | --- | --- |

| `POST /auth/register` | `{username, password}` | `AuthModel`（`role` 可省略） | ✅ |
| `GET /stalls` | `StallDto[]`：`stall_id/status/gender/used_seconds` | 15 条，字段一致 | ✅ |
| `POST /queue` | `{user_id, stall_id?}` → `{ticket_id, position, estimated_wait, stall_id}` | 一致；需 Bearer | ✅ |
| `POST /queue/cancel` | `?ticket_id=` | 一致；需 Bearer | ✅ |
| `POST /feedback/fault` | `{stall_id, reason, detail, user_id}` | 一致；`reason` 需在 7 项枚举内 | ⚠️ 见问题 5 |
| `GET /predict` | 7 个字段 | `queue_length/idle_stalls/avg_duration_used/wait_seconds/wait_minutes/level/current_hour` | ✅ |
| `GET /recommend` | `level/suggestion/idle_stalls/queue_length` | 一致 | ✅ |

## 4. 路由守卫修复与影响确认

### 4.1 根因

原守卫对 `/login` 也执行「未登录 → 跳 `/login`」：

```
访问 /login → 守卫返回 /login?redirect=/login → 再次触发守卫 → …
```

Vue Router 检测到无限重定向后中止导航，`#app` 无内容 → **白屏**。

### 4.2 本次修复

`frontend/src/router/index.ts`：把 `/login` 的判断提到最前面，未登录直接放行 `return true`；已登录访客按角色分流 `/` 或 `/admin`。其余逻辑保持不变。

### 4.3 行为矩阵（修复后）

| 身份 | 访问 `/login` | 访问 `/admin/login` | 访问 `/admin*` | 访问 C 端页 |
| --- | --- | --- | --- | --- |
| 未登录 | 放行 | 放行 | 跳 `/admin/login` | 跳 `/login?redirect=...` |
| 普通用户 | 跳 `/` | 放行 | 跳 `/admin/login` | 放行 |
| 管理员 | 跳 `/admin` | 跳 `/admin` | 放行 | 跳 `/admin` |

登录成功后的回跳仍使用 `route.query.redirect`，未受影响。

> 注意：本地仓库当前没有 `origin/integration` 分支（`git branch -a` 仅有 `main`）。你推送修复后的 `integration` 后，需要先 `git fetch origin`，再以它为基线核对，避免覆盖我这边的改动。
