## 交付摘要

**已完成**：10 个路由页面；登录/注册/权限隔离；隔间状态与 WebSocket 实时推送；预约/取号/取消/报修；扫码入场核销；管理后台工单与维修操作；刷新恢复票号。

**未完成**：排队人数真实值、扫码离场与洗澡报告后端化、用水高峰/翻台率统计、多楼栋支持（详见第 6 节）。

**已知问题**：离线账号仅存于当前浏览器；多楼栋仍需后端提供楼栋维度接口（详见第 5 节）。

**需其他模块配合**：`/stats` 排队人数、WebSocket 建连快照补发、401 语义、离场/统计接口（详见第 8 节）。

**安全合规**：不含 `node_modules/`、`.venv/`、`dist/`、日志与缓存；不含真实密钥或 Token；JWT 密钥支持环境变量，管理员账号由后端预置并可用环境变量覆盖。

## 1. 启动方法

### 1.1 依赖

| 组件 | 版本/地址 | 说明 |
| --- | --- | --- |
| Node.js | 18+ | 前端构建 |
| Python | 3.10+（项目内 `.venv`） | 后端运行 |

### 1.2 启动命令

```powershell
# 1) 确认 Redis 已监听 6379
netstat -ano | findstr :6379

# 2) 启动后端（在项目根目录）
.\.venv\Scripts\python.exe -m uvicorn main:app --port 8000

# 3) 启动前端
cd frontend
npm install        # 首次运行
npm run dev -- --host
```

- 健康检查：`GET http://127.0.0.1:8000/health`
- 接口文档：`http://127.0.0.1:8000/docs`
- `start.bat` **默认只启动前端**，后端启动行是注释状态，需手动执行上面的 uvicorn 命令。

### 1.3 验证结果（本次）

- `npm run build`（`vue-tsc -b && vite build`）通过，1062 个模块，无类型错误。
- Vite 开发服务器所有关键模块（`main.ts`、`App.vue`、`router/index.ts`、各 View）均返回 200。
- 后端 `/health` 返回 `{"status":"ok","redis":"ok","version":"4.0.0"}`。

## 4. 路由守卫修复与影响确认

### 4.1 根因

原守卫对 `/login` 也执行「未登录 → 跳 `/login`」：

```
访问 /login → 守卫返回 /login?redirect=/login → 再次触发守卫 → …
```

Vue Router 检测到无限重定向后中止导航，`#app` 无内容 → **白屏**。

### 4.2 本次修复

`frontend/src/router/index.ts`：把 `/login` 的判断提到最前面，未登录直接放行 `return true`；已登录访客按角色分流 `/` 或 `/admin`。其余逻辑保持不变。

### 4.3 行为矩阵（修复后）

| 身份 | 访问 `/login` | 访问 `/admin/login` | 访问 `/admin*` | 访问 C 端页 |
| --- | --- | --- | --- | --- |
| 未登录 | 放行 | 放行 | 跳 `/admin/login` | 跳 `/login?redirect=...` |
| 普通用户 | 跳 `/` | 放行 | 跳 `/admin/login` | 放行 |
| 管理员 | 跳 `/admin` | 跳 `/admin` | 放行 | 跳 `/admin` |

登录成功后的回跳仍使用 `route.query.redirect`，未受影响。

> 仓库已提供 `origin/integration`，本分支已合并该基线；后续开发前建议先 `git fetch origin && git merge origin/integration`。
